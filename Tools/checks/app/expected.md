# App checks: the shell and the list of the team's rules

`run.sh <commitfence program> <pictures folder>` builds `Tools/CF.App.Check` and runs it. The check program makes its own scratch
folder under the system's temporary folder and points both programs' data folder (`COMMITFENCE_DATA_FOLDER`) into it. For every case it
makes a fresh sample repository: a folder named `invoicing`, `git init -b main`, a copy of the root `commitfence.json` (the repository's rules
TEAM010, TEAM011, TEAM012 and TEAM013, all on, all blocking), and then `commitfence rules disable TEAM012` so that the list has a rule
that is off. The app's real main window is opened on the folder headless (Avalonia.Headless with Skia), at 1440 by 900 unless the case says
otherwise. The command-line program is the first argument of the script. Nothing is written outside the scratch folder and the pictures folder.

Every line is printed as `PASS  <case>: <what must be seen>` or `FAIL  <case>: ...` with the detail lines under it, and the run ends with a
`TOTAL:` line. A case that cannot be carried out (an exception) is printed as a FAIL with the exception.

Tokens (light then dark): `side` #F5F5F5, #202020; `page` #FFFFFF, #262626; `here` #2450E6, #8FA8FF; `on` #1C1C1C, #EDEDED;
`on-knob` #FFFFFF, #1F1F1F; `off` #767676, #8C8C8C.

| --- | --- | --- |
| `rows` | `commitfence rules list` is run in the sample folder; the window's rows are read | the same rules in the same order with the same effect (block or warn), the same off marker (TEAM012 is off), the same titles; and every title is drawn as text in the window |

# App checks: Try it

These cases use the same sample folder (rules TEAM010 to TEAM013, TEAM012 off) and the
same command-line program. "The box" is the code box under "Try it" on the page of a team rule and of a new rule. Code is put in the box the way
a person's typing and pasting does: the editor's text is set, and the box then runs the rule on its own. "The sample" is the sample code of 16 lines
in the check program and "the sample without public" is the same text with `public ` taken off line 1, because the command line
says the reader does not accept a top-level `public` method ("does not parse: The modifier 'public' is not valid for this item", line 1). Every
comparison with the command line is on the text it prints for the same code in a file, with `rules try`.
